# ADR-002: Persistencia de datos mediante MySQL

**Estado:** Propuesto

## Contexto
El Sistema Básico de Control de Inventario para un Centro Naturista necesita almacenar los productos naturales y sus cantidades disponibles. La información debe conservarse entre sesiones y mantenerse consistente cuando se registren o actualicen productos.

## Decisión arquitectónica
Se propone utilizar MySQL como sistema de gestión de base de datos relacional centralizada. Los productos tendrán un identificador único, nombre, precio y cantidad disponible. Se utilizarán restricciones de integridad y transacciones para proteger las actualizaciones del inventario.

## Atributo de calidad protegido
Integridad de datos. El sistema debe evitar registros inconsistentes, cantidades negativas y pérdidas de información durante las operaciones.

## Alternativa considerada
Guardar los productos en archivos locales, por ejemplo, archivos JSON o CSV.

## Justificación
La elección del almacenamiento es difícil de cambiar porque una migración posterior requiere trasladar registros, modificar consultas y conexiones, adaptar componentes y comprobar que las cantidades se mantienen correctamente.

## Consecuencias
**Positivas:** almacenamiento centralizado, consultas estructuradas, restricciones de integridad y soporte de transacciones.

**Negativas:** requiere configurar y administrar MySQL, controlar el acceso y realizar copias de seguridad.

## Escenario de calidad propuesto
Cuando un empleado actualice la cantidad de un producto válido, una consulta posterior deberá mostrar la última cantidad confirmada. Si intenta registrar una cantidad negativa, el sistema deberá rechazarla.

## Evidencia documental
Este ADR registra la decisión propuesta. Su implementación deberá verificarse posteriormente mediante el esquema SQL, las restricciones de la base de datos y pruebas de actualización del inventario.
