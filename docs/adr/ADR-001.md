# ADR-001: Separación de la arquitectura en capas

**Estado:** Propuesto

## Contexto
El Sistema Básico de Control de Inventario para un Centro Naturista permitirá registrar productos naturales, consultar existencias y actualizar cantidades. Es necesario organizar sus componentes para facilitar modificaciones futuras sin afectar todo el sistema.

## Decisión arquitectónica
Se propone utilizar una arquitectura en capas, separando la presentación, la lógica de negocio y el acceso a datos.

- Presentación: interfaz utilizada por el empleado para gestionar productos.
- Lógica de negocio: validación de datos y reglas de actualización del inventario.
- Acceso a datos: operaciones de consulta y almacenamiento en MySQL.

## Atributo de calidad protegido
Mantenibilidad. La separación de responsabilidades permite modificar una capa con menor impacto sobre las demás.

## Alternativa considerada
Desarrollar todas las funcionalidades en un único componente, mezclando interfaz, reglas de negocio y acceso a datos.

## Justificación
La separación en capas es una decisión arquitectónica difícil de cambiar porque, si las responsabilidades estuvieran mezcladas, reorganizarlas posteriormente exigiría modificar dependencias, redistribuir código y ejecutar nuevas pruebas.

## Consecuencias
**Positivas:** facilita el mantenimiento, la organización del código y las pruebas por componentes.

**Negativas:** requiere definir contratos entre capas y mantener una estructura inicial más organizada.

## Escenario de calidad propuesto
Modificar el diseño de la pantalla de consulta de productos sin cambiar las reglas que validan las cantidades del inventario.

## Evidencia documental
Este ADR registra una decisión propuesta para el diseño del sistema. Su aplicación deberá verificarse posteriormente mediante código y pruebas.
